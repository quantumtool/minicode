# MVP 产品需求文档：明天中午12点吃饭提醒 Web 应用

## 1. 产品定位
一个轻量级的单次定时提醒 Web 工具，帮助用户在指定时间（默认为明天中午12:00）通过浏览器通知或弹窗主动触发“吃饭”提醒，解决用户因忙碌或专注而错过饭点的问题。产品聚焦“一次设置、准时提醒”的极致体验，无需登录、无需安装。

## 2. 目标用户
- 学生、上班族等需要准时吃饭但容易忘记的人
- 对复杂提醒工具（如日历、闹钟App）有抗拒感，希望极简操作的用户
- 任何有“明天中午12点提醒我吃饭”临时需求的人

## 3. 核心使用场景
- **场景一**：晚上或早上想起明天中午要吃饭，打开网页，默认时间已设为明天12:00，点击“设置提醒”即可，到点浏览器弹出通知。
- **场景二**：用户临时改变计划，需要取消已设置的提醒，点击“取消提醒”按钮。
- **场景三**：用户希望自定义提醒内容（如“记得吃午饭”），可修改文本框内的默认文字。

## 4. MVP 功能列表
| 功能模块 | 具体功能 | 描述 |
|---------|---------|-----|
| 提醒设置 | 默认提醒时间 | 自动计算并显示明天的 12:00（基于用户本地时区） |
| | 提醒内容输入 | 提供文本框，默认文字为“该吃饭啦！” |
| | 设置提醒按钮 | 点击后开始倒计时，并在浏览器中注册一个定时提醒（使用 setTimeout + Notification API） |
| 提醒触发 | 浏览器通知 | 当时间到达时，若获得通知权限，弹出系统通知（标题“吃饭提醒”，内容为用户输入的文字） |
| | 页面内弹窗 | 若通知被拒绝或无权限，在页面内显示一个醒目的弹窗 + 音效（使用 Web Audio API 或简单 beep） |
| 提醒管理 | 取消提醒 | 点击“取消提醒”按钮，清除已设置的定时器，并重置界面 |
| 状态反馈 | 倒计时显示 | 设置成功后，页面显示距离提醒时间的剩余时间（时:分:秒，每秒更新） |
| | 设置成功/失败提示 | 设置成功后显示绿色提示“✅ 提醒已设置”；若浏览器不支持通知则提示“⚠️ 本浏览器不支持通知，将使用页面弹窗” |
| 界面要求 | 极简卡片式布局 | 一个居中卡片，包含时间和内容输入、两个按钮、倒计时区域，背景柔和，移动端适配 |

## 5. 暂不开发的功能
- 多提醒（同时设置多个不同时间）
- 重复提醒（每天/每周）
- 后端存储或用户账户系统
- 提醒历史记录
- 自定义音效或主题
- 跨设备同步
- 手动输入任意未来日期（仅支持明天12:00，可扩展但 MVP 不做）

## 6. 验收标准
1. **默认值准确性**：用户在任何时区打开页面，默认显示的日期时间应为运行时刻的“明天中午12:00”（例如，若当前为 2025-04-01 14:30，则默认显示 2025-04-02 12:00）。
2. **设置提醒核心流程**：用户点击“设置提醒”后：
   - 若浏览器支持 `Notification` 且用户已授权，到点后显示系统通知。
   - 若用户拒绝或浏览器不支持，到点后页面内弹窗并播放简短提示音（声音持续 1 秒）。
3. **取消提醒**：点击“取消提醒”后，倒计时停止，所有定时器清除，界面重置，并显示“提醒已取消”。
4. **倒计时准确性**：倒计时应每秒更新一次，误差不超过 1 秒。当剩余时间小于 0 时，停止更新并触发提醒。
5. **内容自定义**：用户修改提醒内容文本框后，设置提醒时使用该内容；若内容为空，提醒时默认显示“该吃饭啦！”。
6. **异常处理**：
   - 若用户关闭页面再重新打开，已设置的提醒不再生效（MVP 不做持久化）。
   - 若用户设置提醒时浏览器处于后台或休眠，到点时 `setTimeout` 仍应触发（大多数现代浏览器会延迟但不会丢失超过几分钟的定时器，符合 MVPL 要求）。
7. **浏览器兼容性**：在 Chrome、Firefox、Edge、Safari 最新版本中均可正常工作（Safari 不支持 `Notification` 权限时回退到页面弹窗+音效）。
8. **移动端适配**：在手机浏览器（iOS Safari / Android Chrome）上，页面布局完整，按钮大小适合手指点击，倒计时清晰可见。

---

**备注**：以上文档基于用户“明天中午12吃饭提醒”的单一需求，但 MVP 设计保留了可扩展性（如未来增加自定义日期选择、重复提醒等），可在后续迭代中逐步添加。
